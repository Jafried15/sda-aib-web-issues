## Wofür ist dieses Repository?

Dieses Repository ist der zentrale Ort, um:

- **Fehler** in der Adventgemeinde Bad Aibling Website zu melden, die du beim Benutzen festgestellt hast.
- **Neue Funktionen** oder Verbesserungen vorzuschlagen, die dir die Arbeit erleichtern würden.

Die Entwicklerin / der Entwickler kann so alle Rückmeldungen an einem Ort einsehen, priorisieren und bearbeiten.

## Einen Fehler melden (Bug Report)

Ein **Fehler (Bug)** liegt vor, wenn die Anwendung sich unerwartet verhält, abstürzt oder eine Funktion nicht wie beschrieben funktioniert.

### Schritt-für-Schritt-Anleitung

1. Klicke oben auf den Reiter **„Issues"**.
2. Klicke auf den grünen Button **„New issue"**.
3. Wähle die Vorlage **„Bug Report"** aus (falls vorhanden), oder vergib einen aussagekräftigen Titel, z. B.:  
   `Fehler: Anmeldeformular akzeptiert kein Passwort`
4. Fülle die Beschreibung mit folgenden Angaben aus:

| Feld | Beschreibung |
|---|---|
| **Was ist passiert?** | Beschreibe kurz, was du erlebt hast. |
| **Was hast du erwartet?** | Was hätte die Anwendung deiner Meinung nach tun sollen? |
| **Schritte zur Reproduktion** | Beschreibe Schritt für Schritt, wie man den Fehler nachvollziehen kann. |
| **Screenshots / Fehlermeldungen** | Füge wenn möglich einen Screenshot oder den genauen Fehlertext ein. |
| **Browser & Gerät** | Z. B. „Chrome auf Windows 11" oder „Safari auf iPhone 14". |

5. Klicke auf **„Submit new issue"**, um das Ticket einzureichen.

### Beispiel

> **Titel:** Fehler: Seite lädt nicht nach dem Login  
> **Beschreibung:**  
> Nach der Anmeldung mit meinen Zugangsdaten zeigt die Seite nur eine weiße Seite an.  
> Ich habe erwartet, dass ich auf das Dashboard weitergeleitet werde.  
>  
> **Schritte:**  
> 1. Startseite aufrufen  
> 2. E-Mail und Passwort eingeben und auf „Anmelden" klicken  
> 3. Weiße Seite erscheint  
>  
> **Browser:** Firefox 125 auf macOS Sonoma

## Einen Funktionswunsch einreichen (Feature Request)

Ein **Funktionswunsch (Feature Request)** ist ein Vorschlag für eine neue Funktion oder eine Verbesserung, die es bisher nicht gibt.

### Schritt-für-Schritt-Anleitung

1. Klicke oben auf den Reiter **„Issues"**.
2. Klicke auf den grünen Button **„New issue"**.
3. Wähle die Vorlage **„Feature Request"** aus (falls vorhanden), oder vergib einen klaren Titel, z. B.:  
   `Wunsch: Dunkelmodus für die Benutzeroberfläche`
4. Fülle die Beschreibung mit folgenden Angaben aus:

| Feld | Beschreibung |
|---|---|
| **Was ist dein Wunsch?** | Beschreibe kurz, was du dir wünscht. |
| **Warum wäre das hilfreich?** | Erkläre, welches Problem damit gelöst werden würde. |
| **Wie könnte es aussehen?** | Falls du eine konkrete Vorstellung hast, beschreibe sie oder füge eine Skizze ein. |

5. Klicke auf **„Submit new issue"**, um den Vorschlag einzureichen.

### Beispiel

> **Titel:** Wunsch: Export der Daten als Excel-Datei  
> **Beschreibung:**  
> Ich würde mir wünschen, dass ich die angezeigten Daten als Excel-Datei herunterladen kann.  
> Das wäre hilfreich, weil ich die Daten regelmäßig in unsere interne Tabelle übertragen muss und das aktuell manuell passiert.  
>  
> Eine einfache Schaltfläche „Als Excel exportieren" in der Tabellenansicht wäre ideal.

## Tipps für gute Tickets

Gute Tickets helfen dabei, Probleme schneller zu lösen und Wünsche besser zu verstehen. Beachte folgende Punkte:

- ✅ **Ein Thema pro Ticket** – Mische nicht mehrere Fehler oder Wünsche in einem Ticket.
- ✅ **Klarer Titel** – Der Titel sollte das Problem oder den Wunsch auf einen Blick erkennbar machen.
- ✅ **So viel Detail wie nötig** – Je genauer du beschreibst, was passiert ist, desto einfacher ist es, den Fehler zu finden.
- ✅ **Screenshots sind Gold wert** – Ein Bild sagt mehr als tausend Worte, besonders bei Darstellungsfehlern.
- ❌ **Nicht doppelt einreichen** – Schaue vorher kurz nach, ob ein ähnliches Ticket bereits existiert (Suchfeld oben auf der Issues-Seite).

## Wie geht es nach dem Einreichen weiter?

Nach dem Einreichen eines Tickets durchläuft es folgende Phasen:

| Status | Bedeutung |
|---|---|
| **Open** (Offen) | Das Ticket wurde eingereicht und wartet auf Sichtung. |
| **In Progress** (In Bearbeitung) | Ein Entwickler hat das Ticket aufgenommen und arbeitet daran. |
| **Resolved / Closed** (Gelöst / Geschlossen) | Das Problem wurde behoben oder der Wunsch umgesetzt. |
| **Won't Fix / Declined** (Wird nicht umgesetzt) | Das Ticket wird nicht bearbeitet – ein Kommentar erklärt den Grund. |

Du kannst den Status jederzeit nachverfolgen, indem du auf der Issues-Seite nach deinem Ticket suchst. Du erhältst auch eine Benachrichtigung per E-Mail, wenn jemand deinen Beitrag kommentiert oder der Status sich ändert – sofern du bei GitHub angemeldet bist.

## Häufige Fragen (FAQ)

**Brauche ich ein GitHub-Konto, um ein Ticket einzureichen?**  
Ja, für das Einreichen eines Tickets ist ein kostenloses GitHub-Konto erforderlich. Die Registrierung ist schnell und kostenlos unter [github.com](https://github.com) möglich.

**Wo ist der Quellcode der Anwendung?**  
Der Quellcode befindet sich in einem privaten Repository und ist nicht öffentlich zugänglich. Dieses Repository hier dient nur der Kommunikation über Fehler und Wünsche.

**Mein Ticket wurde geschlossen, aber das Problem besteht noch.**  
Schreibe einen Kommentar in das bestehende Ticket und schildere, dass das Problem weiterhin auftritt. Füge aktuelle Screenshots oder weitere Details hinzu.

**Kann ich auf Englisch schreiben?**  
Ja, Tickets auf Englisch werden ebenfalls akzeptiert und bearbeitet.
